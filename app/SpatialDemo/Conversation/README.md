# Realtime conversation

`RealtimeSession` owns one native WebSocket conversation for typed text and speech. `DemoSessionModel` supplies selection snapshots and an asynchronous scene-tool executor; this directory has no server-rack operations or RealityKit dependency.

1. **Connect** obtains an ephemeral credential from `POST /realtime/client-secret` and waits for `session.updated`. This does not request microphone permission or start audio capture.
2. **Typed input** sends a user `conversation.item.create` with `input_text`. **Voice input** streams 24 kHz mono signed PCM16 from `AudioIOController`; local onset captures selection, and the server's committed audio item starts a turn. Transcription is display data, not a second scene request.
3. An initial `response.create` forces one `ask_astra` function with `{request: string}`. Initial text preambles are hidden. Only a completed `response.done` with matching turn metadata and valid arguments can invoke the executor.
4. The executor calls the existing Astra scene service. The service uses `gpt-6-astra` to author a complete `propose_scene` result. `SceneController.execute` waits for matching receipts and explanation, or returns a terminal failure/cancellation.
5. The exact `call_id` receives a `function_call_output` containing status, request ID, scene/revision/epoch, proposal IDs, and explanation/error. If this is still the active turn, a second `response.create` disables tools and requests text for a typed turn or audio plus transcript for a spoken turn.

The forced one-tool policy permits one scene execution per turn. Realtime reformulates the request; its function arguments do not supply authoritative node IDs, scene versions, or installation claims. This is one conversational interface with a separate scene executor, not one model or one physical network connection.

## Audio and turn ownership

[`AudioIOController`](AudioIOController.swift) keeps engine and UI control on `MainActor`. The tap uses an explicit `@Sendable` callback and nonisolated, `Sendable` gate/converter helpers with mutex-protected state. It converts the device format with `AVAudioConverter`, copies PCM bytes, and yields into an `AsyncThrowingStream` bounded to eight chunks of at most 32 KiB each. One consumer in [`RealtimeSession`](RealtimeSession.swift) admits these chunks; overflow or oversize terminates capture visibly. No task is created for every tap buffer. Permission and playback completion callbacks are also explicit `@Sendable` boundaries; playback completion returns to `MainActor` before touching session state. Apple documents that [tap callbacks may run away from the main thread](https://developer.apple.com/documentation/avfaudio/avaudionode/installtap%28onbus%3Abuffersize%3Aformat%3Ablock%3A%29) and exposes a [`@Sendable` playback completion handler](https://developer.apple.com/documentation/avfaudio/avaudioplayernode/schedulebuffer%28_%3Acompletioncallbacktype%3Acompletionhandler%3A%29).

[`RealtimeWire`](RealtimeWire.swift) keeps `server_vad` enabled with threshold `0.5`, prefix padding `300 ms`, and silence duration `450 ms`, but sets **`create_response: false` and `interrupt_response: false`**. The client explicitly creates and cancels responses, as supported by [Realtime's VAD controls](https://developers.openai.com/api/docs/guides/realtime-conversations#keep-vad-but-disable-automatic-responses). Local energy onset is only a selection hint: it cannot cancel a pending tool response or audible output. A validated server `speech_started` event authorizes barge-in; its committed item starts the next turn.

Each chunk and selection hint carries a capture UUID. Resetting capture rotates that UUID, drops queued old audio, and serializes `input_audio_buffer.clear`; input remains blocked until its acknowledgment. The outbound drain maintains the cumulative sent-frame clock and stamps a capture floor when sending the clear. Server VAD timestamps must fall within that clock, after the floor and previous admitted onset, and bind to selection recorded in the current capture. If there is no usable energy onset, bounded selection history supplies the snapshot at the server onset plus configured prefix padding. The acknowledgment alone does not admit delayed events from an older capture.

Interruption stops presentation and truncates provider audio at completed playback-buffer time. It does not turn an actual scene result into a fabricated cancellation: a returning executor result still queues the original call's terminal `function_call_output` on the same live connection. A superseded turn cannot request a new final response. This is not durable delivery across disconnects. The [function-calling protocol](https://developers.openai.com/api/docs/guides/realtime-conversations#function-calling) associates output with the exact `call_id`; the client additionally requires a completed `response.done` with matching turn metadata before executing a call.

Audio callbacks update raw counters; a timer formats capture summaries away from the callback. Consumer PCM, send queues, server VAD, tool results, and playback have separate events without raw audio or text. See [diagnostics](../../../docs/diagnostics.md).

## Acceptance boundary

The [provider smoke](../../../docs/evidence/realtime-tools-smoke.json) tested forced tools, metadata, and final text/audio with synthetic scene results. On 2026-09-08, physical iPhone permission, capture, conversion, and two server utterance/transcription events were observed. That run exposed premature cancellation by local onset; the current code uses server-authorized interruption as described above. A complete physical spoken request → scene result → audible reply remains unproven. See [acceptance evidence](../../../docs/evidence/README.md) for separately scoped receipts.

The unhosted `RealtimeSessionTests` target compiles these production sources with deterministic socket/audio dependencies. Run `xcodebuild test -project app/AstraSpatialDemo.xcodeproj -scheme AstraSpatialDemo -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -only-testing:RealtimeSessionTests CODE_SIGNING_ALLOWED=NO` from the repository root. [Native repair evidence](../../../docs/evidence/native-realtime-audio.json) separates these regressions from physical capture and reply observations.
